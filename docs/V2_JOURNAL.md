## 1. 대사 즉시 표시
- 이미 구현되어 있었다(`onStageClick`: 타이핑 중 클릭 → 전체 표시, 완료 후 클릭 → 다음 대사. 선택지는 클릭으로 건너뛰지 못한다. Enter·Space 동일).
- 이번 보강: 클릭으로 전체가 표시된 뒤 남은 타이머 틱이 글자 수를 되돌릴 수 있던 결함을 단조 증가 갱신(`Math.max`)으로 수정. 회귀 테스트 추가(`journal.test.tsx`).

## 2. 세계관 용어집
- **노출 방식 3가지**: ① 해리의 서술·대사에서 처음 나올 때 한두 문장 설명(챕터 1: N.E.W.T./O.W.L., 감독생), ② 대사 속 용어에 점선 밑줄 버튼(클릭·터치·Enter) → 설명창, ③ 메뉴 "세계관 용어집"에서 다시 열람.
- 용어 해금: `GameState.terms`(선택 필드)에 대사를 넘길 때(`advance`)·선택할 때 기록. 이전 저장은 남은 대화 기록(최대 200)에서 보정. 지금 화면의 글에 나온 용어는 즉시 열람 가능.
- 스포일러 정책: 설명은 원작 일반 상식 수준이며 이 작품의 비밀·미래 사건을 쓰지 않는다(금지어 테스트). 마주치지 않은 용어는 이름도 개수도 보이지 않는다. 용어 설명창을 열면 자동·스킵이 멈추고, 닫아도 대사는 넘어가지 않는다(클릭 비전파).
- 용어 추가: `glossary.ts`에 항목 추가(별칭은 전체에서 유일해야 한다). 기본은 챕터 1~2에서 쓰이는 20개 항목.

## 3. 인물 관찰 기록
- **원칙**: 정답지가 아니라 해리의 관찰(직접 본 것)과 주관적 해석(내 생각). 호감도·신뢰도·관계 단계·연애 상태·지식 단계(`know`)는 **조건으로도 쓰지 않는다**. 해리가 경험한 사건(선택 이력 `CH_*`, 관찰 `OB_*`·`KN_*`, 사건 표식 `FLAG_*`, 만남 횟수 `seen.<id>`)만 근거다.
- **구조**: 인물 탭(만난 인물만) → 아는 것 / 요즘 받은 인상 / 직접 본 것 / 내 생각 / 달라진 점. 이미지 없음.
- **파생**: 저장하지 않는다. `buildJournal(state)`가 현재 상태에서 결정적으로 계산하므로 저장·불러오기·가져오기 후에도 같은 결과다.
- **충돌 규칙**: 인상·내 생각은 조건이 참인 항목 중 `prio`가 가장 높은 하나(동점이면 뒤에 정의된 항목). 달라진 점은 `prio` 상위 2개. 아는 것·직접 본 것은 참인 항목을 사건 순서대로 모두 표시.
- **갱신 트리거**: 첫 만남(`seen`), 선택(`CH_*`), 관찰(`OB_*`/`KN_*`), 사건 표식(`FLAG_*`). 챕터 번호만으로 문장을 바꾸지 않는다. 사소한 수치 변화는 반영하지 않는다(수치를 읽지 않는다).
- **알림 없음**: 갱신 알림·새 항목 표시·잠긴 탭 이름은 두지 않는다(누출 방지). 열람은 읽기 전용이라 시간·수치가 바뀌지 않는다.
- **새 사건 표식(챕터 1에서 추가, 후속 참조 = 관찰 기록)**: `FLAG_HR1_HER_PAPER`(헤르미온느 논문 두 번째 만남), `FLAG_HR1_GIN_CAPTAIN`(지니 주장 이야기), `FLAG_HR1_LUN_LAKE`(루나 호수 지도), `FLAG_HR1_PAN_MIRROR`(판시 거울), `FLAG_HER_LEFT_OUT`(`REACT_hermione_ginny == 4` 반응을 본 뒤), `FLAG_LUN_SAW_HER`(`REACT_luna_hermione == 3` 반응을 본 뒤). 모두 장면 끝 `fx`로만 설정.
- **현재 범위**: 프롤로그~챕터 1(조건부 문장 항목: 드레이코 44·헤르미온느 19·지니 22·루나 14·판시 20). 챕터 2 이후는 같은 형식으로 항목을 추가하며, 변신 이후 문장은 장면에서 해리가 실제로 알게 된 다음에만 조건을 연다.
- **드레이코**: 감정을 단정하지 않는다. 행동의 모순(거절하면서 손은 이미 거기 감, 시비를 걸러 와서 안부를 물음)을 쌍으로 기록하고, 로맨스/라이벌 어느 쪽이든 같은 사실에서 출발해 해석 문장만 선택 이력에 따라 갈린다.
- **테스트**(`journal.test.tsx`): 시작 상태 공백, 목격 전 사건 비노출, 선택별 상이, 우선순위, 수치·연애·know 변화에 불변, 저장 복원 동일, 금지어·내부명 부재, 조건식이 가리키는 플래그·선택지의 실재 확인.

## 4. 반응 훅 설계 메모(챕터 1)
- `REACT_<관찰자>_<대상>`은 `meet:` 효과가 기록한 최근 3일의 만남에서 **관찰자가 증인이었는지**와 관찰자의 단계·연애 상태로 정해진다. 히로인 이벤트는 장면 시작 전에 이번 만남을 기록하므로, 같은 자리에 있던 관찰자의 반응을 그 장면 안에서 바로 쓸 수 있다.
- 장면에서 쓸 만한 훅은 "관찰자가 일정표상 대상과 같은 장소·시간에 자주 있고, 시작 단계의 반응 종류가 고정된" 경우뿐이다(루나=호기심, 헤르미온느=서운함). 지니·판시는 시작 단계의 반응이 무관심이라 단계가 오르기 전에는 훅이 거의 열리지 않는다 → 챕터 2 이후 단계가 오른 뒤에 추가한다.
- 도달성 감사(`reach.test.ts`)가 각 반응 조건의 참 관측을 강제하므로, 새 훅은 감사를 통과해야 들어간다.
- **발생 빈도 측정(고정 시드 300회, 일상 랜덤 이벤트 켬)**: 헤르미온느 온실 이벤트가 나온 플레이에서는 루나 반응이 항상 나왔다(12/12, 85/85, 190/190 — 루나가 그 시간 온실에 항상 있기 때문). 이벤트 자체가 나오는 비율은 무작위 플레이 4%(12/300), 한 히로인을 따라다니는 플레이 28%(85/300), 온실 위주 플레이 63%(190/300)다. 관계 조건은 완화하지 않았다.
