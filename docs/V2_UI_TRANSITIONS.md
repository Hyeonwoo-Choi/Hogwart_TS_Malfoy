# V2_UI_TRANSITIONS — 선택지 패널 · 지도 레이아웃 · 장면 전환

> 상위: [V2_DESIGN.md](V2_DESIGN.md). 구현: `src/ui/Game.tsx` · `src/ui/MapView.tsx` · `src/styles.css`(하단 블록) · `src/engine/core.ts`(trans) · `src/data/dsl.ts`.

## 1. 선택지와 대사창
- 선택지는 대사창(`.dialogue`) **안**에 놓인다: 프롬프트 → 선택지 목록이 같은 패널(같은 너비·배경·테두리)에 쌓인다. 선택지가 나타나면 스테이지 그리드의 아래 행이 내용 높이로 늘어나 장면 영역이 줄고, 캐릭터·CG는 줄어든 영역 안에서 온전히 보인다(겹침 없음).
- 패널 최대 높이는 화면 높이의 76%(가로 모드는 화면 − 44px)이고 넘치면 패널 안에서만 스크롤한다. 긴 선택지는 줄바꿈한다. CG 프레임은 고정 좌표가 아니라 같은 그리드 행을 따른다.
- 입력: 선택지 클릭은 전파되지 않고, 선택 전에는 대사창 클릭·Enter·Space로 진행되지 않는다. 숫자키 1~9는 그대로다. 선택 ID·효과·`data-testid`는 변경 없음.
- 대사 클릭 즉시 표시(타이핑 중 첫 클릭 = 전체 표시, 완료 후 클릭 = 다음)는 기존 동작 그대로다.

## 2. 자유 일과 지도
- 데스크톱(≥1024px): 헤더(날짜·시간대·남은 시간·넘기기) → 왼쪽 지도(주 영역, 화면 높이에 맞춰 최대한 확대) / 오른쪽 열(장소 설명·활동 패널, 그 아래 접을 수 있는 능력치). 최대 너비 1760px.
- 모바일·태블릿(<1024px): 지도 → 활동 패널 → 능력치 세로 배치. 장소를 고르면 활동 패널로 부드럽게 스크롤한다. 터치 영역 52px 이상, 가로 스크롤 없음.
- 능력치 패널은 접기/펼치기 버튼(`aria-expanded`)이며 좁은 화면(<768px)에서는 접힌 채 시작한다.
- 장소 이름은 `clamp(.84rem…1.1rem)`로 키우고 반투명 바탕을 둬 읽기 쉽게 했다. 장소·좌표·활동 조건·시간 소모·랜덤 이벤트·저장 데이터는 변경 없음.

## 3. 장면 전환(trans)
- 시나리오: `trans('그날 저녁', '호그와트 · 대연회장')` 노드(제목 + 선택적 장소). 의미 있는 시간 경과·장소 이동의 **장면 맨 앞**에만 쓴다. 모든 노드에 강제하지 않는다.
- 동작: 앱에서는 엔진이 이 노드에서 멈추고(`setTransitions(true)`, 앱에서만 켜짐), UI가 ① 현재 장면 페이드아웃(0.45s) ② 어두운 화면에 문구(1.5s) ③ `advance`로 다음 장면 시작 + 페이드인(0.52s)을 재생한다. 테스트·꺼진 환경에서는 노드를 건너뛴다.
- 입력: 전환 중 클릭·Enter·Space는 무시된다(베일이 화면을 덮고, 대사·선택지가 없는 노드라 진행 입력이 닿지 않는다). 용어 설명·메뉴는 그대로 열 수 있다. 스킵 중에는 기다리지 않고 지나간다.
- 저장·불러오기: 위치는 trans 노드에 머물러 있고 재생이 끝나야 다음으로 넘어가므로 불러와도 **한 번만** 재생된다(`view.cue`처럼 상태에 재생 횟수를 저장하지 않는다).
- 움직임 감소(`prefers-reduced-motion`): 페이드 없이 문구만 잠시 표시하고 바로 전환한다.
- 챕터 1 적용: 연회 `그날 저녁 · 대연회장`, 마법약 `다음 날 오후 · 마법약 교실`, 경기장 `다음 날 오후 · 퀴디치 경기장`, 자유 일과 `다음 날 방과 후 · 호그와트`, 7층 밤 `토요일 밤 · 통금이 지난 시간`(장소명으로 7층을 미리 알리지 않는다), 일요일 `다음 날 아침 · 대연회장`. 요일은 각 장면의 `date` 노드·드레이코 일정표와 일치한다. 챕터 종료→챕터 2 진입은 기존 종료 카드를 유지(미적용).

## 4. 키퍼 선발 시점(챕터 1 ↔ 챕터 8)
- 챕터 8(2월)은 "키퍼 선발이 다음 달"(주전 확정 3월)이라 쓴다. 챕터 1의 공지는 이를 **평가 연습 시작(9월) + 주전 확정은 겨울이 지난 뒤**로 고쳐 같은 사건의 두 단계로 정리했다. 챕터 8 본문과 H-07 선택 ID·효과는 변경 없음. 론의 종료 훅 대사도 "한참 뒤의 주전 확정까지 매일 일곱 번"으로 맞췄다.

## 5. 용어 읽음 상태 (구현: `GameState.termsRead`, `readTerm`, `store.markTermRead`, `ui/Terms.tsx`)
- 세 상태: 미등장(보이지 않음) / 등장했지만 안 읽음(금색 점선) / 읽음(회색 `#aab0ba`, 점선, 재클릭으로 다시 열림). 등장 이력 `terms`의 의미는 그대로이고 읽음은 별개 목록이다. 설명창을 열면(또는 용어집에서 항목을 펼치면) 읽음이 되며 대사는 넘어가지 않는다.
- 용어집 목록은 접힌 항목(이름·요약)으로 시작해 펼칠 때 읽음 처리한다. 안 읽은 항목은 금색 + 점(●), 읽은 항목은 회색. 아직 마주치지 않은 용어는 이름도 개수도 보이지 않는다.
- 저장: 세이브의 `state.termsRead`(선택 필드). 이전 저장은 불러올 때 빈 목록으로 보정한다.

## 6. 자유 일과 지도 보강
- 활동 패널은 장소가 바뀔 때 `key`로 교체되며 0.22초 페이드·슬라이드(`panel-in`)로 나타난다. 빠르게 여러 장소를 눌러도 패널은 하나이고 마지막 장소의 활동만 보인다. 활동 목록은 `max-height: min(48dvh, 480px)` 안에서 스크롤한다. 설명과 소요 시간·끝나는 때는 점선으로 구분한다.
- 능력치: 장소를 골라 활동 목록이 열리면 자동으로 접는다. 사용자가 직접 펼친 뒤에는 닫지 않으며, 언제든 헤더 버튼으로 다시 펼친다. 높이만 0.25초 전환하고(접힌 동안은 포커스도 받지 않음) 지도 열은 움직이지 않는다. 한 열로 쌓이는 화면(<1024px)에서만 장소 선택 후 활동 패널로 스크롤한다.
- 진입·종료 연출: 자유 일과로 들어갈 때와 끝나 스토리로 돌아올 때(`state.routine` 유무가 바뀔 때) 검은 막이 0.6초에 걸쳐 걷힌다(`mode-fade`). 상태가 이미 바뀐 뒤의 화면을 밝히는 UI 연출이라 입력을 막지 않고 시간 소모와 무관하며, 불러오기 직후·움직임 감소 설정에서는 재생하지 않는다. 장소를 고를 때는 화면 전체 전환이 없다. (지도가 사라지는 쪽의 페이드아웃은 상태 전환이 먼저라 컷으로 처리된다.)

## 7. 마법 이펙트 연결 지점 (`src/ui/effects.ts`)
구독자가 없으면 아무 일도 하지 않는다. 그래픽 쪽은 `onUiEffect(listener)`로 구독한다.
| 신호 | 보내는 곳 | 조건 |
|---|---|---|
| `term-discover` | `useGameEffectSignals` | 대사 진행으로 `terms`가 늘 때 |
| `term-open` (`first`) | `Game.openTerm` | 용어 설명창이 열릴 때(처음 읽음이면 `first: true`) |
| `journal-update` (`id`=인물) | `useGameEffectSignals` | 관찰 기록의 "직접 본 것"이 늘 때 |
| `clue` (`id`=OB_*) | `useGameEffectSignals` | 새 관찰 단서를 얻을 때 |
| `case-update` (`id`=사건) | `useGameEffectSignals` | 사건 수첩의 단서(직접+들은 것)가 늘 때 |
| `transition` (`id`) | `Game` / `useScreenFade` | 시간·장소 전환 시작 / 화면 종류 전환(`map|1>scene|1` 같은 키) |
| `notebook-open` · `notebook-page`(section) · `notebook-close` | `Notebook` | 마법 수첩 열림 · 페이지 전환 · 닫힘 |
- 첫 렌더·불러오기 직후 상태는 기준선이라 신호를 보내지 않는다. 파티클·캔버스·그래픽 라이브러리·에셋은 추가하지 않았다.
- 마법 수첩을 실제 책처럼 꾸밀 때(책 펼침·책장 넘김·잉크 쓰기·단서 빛남)는 `onUiEffect`로 `notebook-open`/`notebook-page`/`case-update`/`journal-update`/`clue`를 받아 `Notebook`의 DOM(`data-testid=notebook`, `nb-page[data-section]`)에 붙이면 된다. 효과가 없어도 모든 기능은 그대로 동작한다.

## 8. 화면 전환 조정 계층 (보정: 지도 ↔ 활동 장면 ↔ 스토리)
- 5장의 `mode-fade`(상태가 먼저 바뀌는 컷)를 **`useScreenFade`로 대체**했다. 게임 상태(store)는 즉시 확정되지만 화면에 보이는 상태(`view`)는 "지도/장면/종료 카드 × 자유 일과 중 여부"가 바뀌는 경계에서만 잠깐 이전 화면에 머문다: 이전 화면 페이드아웃(0.32s, `sv-out`) → 새 화면으로 교체(0.12s, `sv-hold`) → 페이드인(0.38s, `sv-in`).
- 적용 경계: 스토리→지도(진입), 지도→활동 장면, 장면→지도(복귀), 자유 일과 종료→다음 스토리, 장면→챕터 종료 카드·종료 카드→다음 챕터. 장소를 고를 때·장면 안의 대사 사이에는 쓰지 않는다. 활동 장면 → 이어지는 이벤트 장면은 같은 종류라 이어서 재생된다.
- 입력: 막이 덮이는 동안(out·hold) 클릭·키·자동·스킵을 받지 않고(상태는 이미 확정돼 중복 적용 없음), 걷히는 동안은 통과시킨다. 새 게임·타이틀·불러오기·가져오기(`store.epoch` 증가)와 첫 렌더는 전환 없이 바로 보인다(저장 복원에서 재생되지 않음). `prefers-reduced-motion`에서는 즉시 교체. 언마운트 시 타이머를 정리한다.
- 노드 전환(`trans`, 시간·장소 문구)은 그대로이며 이 계층과 독립이다.
