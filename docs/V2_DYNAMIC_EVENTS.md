# V2_DYNAMIC_EVENTS — 돌발 사건(세계 사건)과 랜덤 이벤트

> 상위: [V2_DESIGN.md](V2_DESIGN.md). 기존 47개 랜덤 이벤트(`data/randomEvents.ts`, [RANDOM_EVENTS.md](RANDOM_EVENTS.md))는 변경하지 않았다. 구현: `data/incidents.ts`(정의), `data/v2c1e.ts`(장면), `engine/core.ts`(`incidentFor`), `data/cases.ts`(수첩).

## 1. 구조 [구현]
- **우선순위(활동 직후)**: 드레이코 만남 → 히로인 이벤트 → **돌발 사건** → 조연 일상 → 랜덤 이벤트. 돌발 사건은 메인 쪽 이벤트(만남·히로인)를 덮어쓰지 않고 가벼운 이벤트보다 앞선다. 활동 장면(짧은 s)이 먼저 재생되고 사건은 `routine.after`로 이어진다.
- **선언형**: `Incident { id, places, acts, dates, slots, chance, cond }`. 한 번만(`rev.seen`).
- **재현성**: 확률은 `hash(게임 salt, 사건, 날짜, 시간대, 장소) < chance`로 결정적이다. 같은 상태를 몇 번 불러와도 같은 결과 → 저장·불러오기로 운을 바꿀 수 없고, 난수 소비 순서가 바뀌어 기존 랜덤 이벤트 시드가 어긋나지 않는다. salt는 `rev.salt`(구세이브는 처음 사용 시 현재 난수 상태에서 정해 저장).
- **켜기**: 앱에서만(`setIncidents`). 테스트 기본은 꺼짐. 사건 장면은 시나리오에 포함.
- **안전**: 필수 진행 조건이 아니다(놓쳐도 챕터 진행). 위험 선택에도 영구 차단은 없고 불이익은 능력치 소폭·시간 1칸이다. 캐릭터 일정과 충돌하지 않도록 동료 도움은 `HERE_*`(일정표상 그 자리에 있던 사람)만 응한다.

## 2. 챕터 1 사건 [구현]
- **inc_crack_corridor 「복도 벽의 금」**: 9/4~9/6 오후1·2, 도서관 공부·조사 직후, 확률 50%(결정적). 선택 X-01: A 직접 살핀다(시간 +1, 단서 `OB_CRACK`, 손끝 냉기로 의지 −1) / B 필치에게 알린다(시간 +1, 보수 예정 증언) / C 도움을 청한다(그 자리의 헤르미온느면 측정과 룬 닮음 증언, 판시면 석재 증언, 아무도 없으면 직접 살핌) / D 물러난다(의지 +1). 후속은 A·C일 때만.
- **inc_crack_followup**: 신고하지 않았다면 다음 날 확률 70%. 금이 벌어져 벽감이 열림. X-02: 종이를 가져간다(`OB_CRACK_SKETCH`) / 위치만 적는다.
- **설정 안전**: 이 금을 챕터 2의 캐비닛 사고와 연결하는 문장은 없다. 사건 수첩은 "도면의 매듭과 닮았다"는 추측과 "7층에서 본 톱밥과 같은 종류인가"라는 의문까지만 제시한다. 공통 원인으로 삼으려면 복선·지식 조건을 먼저 설치해야 한다(후속).
- **사건 수첩**: `castle-crack` 사건(직접 본 것 / 필치·헤르미온느·판시의 증언 / 추측 / 의문)이 겪은 방식에 따라 다르게 기록된다(테스트).
- 활동 장면 반영: 금을 본 뒤 도서관 공부 장면에 벽을 의식하는 한 줄이 추가된다.

## 3. 측정 [구현 · 로그]
- 공부하는 학생(도서관 공부·조사를 30% 선택) 40회×6 스타일에서 발생 8%. 도서관 공부를 선호하면 약 20~25%(디버그 측정: 도서관 공부 97회 중 12회). 도서관은 히로인·드레이코 만남이 먼저 소비되므로 첫 두세 번 방문에서는 거의 일어나지 않는다. **희귀한 편이며 필수가 아니다.**

## 4. 설계 [미구현]
- 유형 확장: 일상 소동·관계형·탐험형·위험형·연쇄형(5유형). 현재는 탐험형+연쇄형 일부만 구현. 위험형 구역 통제, 히로인 동행 조사, 연쇄 결론 등록(사건 수첩 "확인된 결론"), 챕터별 사건 풀, 반복 방지 쿨다운 확장.
