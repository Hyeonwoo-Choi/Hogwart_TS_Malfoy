# STORY_FLAG_REQUIREMENTS — 상태·지식·조건 정의안

> 이 폴더의 **설계 상태 단일 원천**. 아래 점 표기는 설명용 자료 구조이며 현재 evalCond/fx 문자열이 아니다.
> 실제 FLAG/KN/OB/선택 ID는 변경·등록하지 않았다. 구현 시 [BRANCH_MAP](../BRANCH_MAP.md)·[V2](../BRANCH_MAP_V2.md)에 먼저 등록하고 기존 선택 이력으로 표현 가능한 사실은 새 플래그를 만들지 않는다.

## 1. 상태를 적게 유지하는 단위

| 설계 필드 | 값·범위 | 기록·용도 |
|---|---|---|
| `case[n].axis` | A/B/C/D/E/neutral, 챕터별 | 현재 주사건. 연애 대상이 아님. 다른 장에서는 같은 A라도 의미가 다름 |
| `case[n].result` | 해당 장의 종결 결과 한 개 | 선택 경로의 고유 결론. 공통 합류에서도 유지 |
| `case[n].method` | official/private/withheld/forced 등 선택 이력에서 파생 | 같은 결론에 이른 방식. 구현 시 기존 CH 참조 우선 |
| `evidence[item]` | held/returned/submitted/lost, 출처·보관자 포함 | 소유권·증거력. 획득한 사실을 반환했다고 기억까지 삭제하지 않음 |
| `knowledge[fact]` | observation/testimony/inference, 출처·시점 포함 | 직접 본 것과 들은 것을 분리. 타인의 비밀과 해리의 추측을 구별 |
| `agreement[topic]` | offered/accepted/declined/kept/broken/repaired | 사건 약속의 이행. 반복 장면에서 중복 갱신 금지 |
| `permission[person,topic]` | denied/limited/allowed, 범위·시점 | 자료 공유·증언·접촉·관계 공개는 별도 주제 |
| `assignment[person]` | 역할·동의·인계 여부 | Ch11~13 준비와 현장 이탈 결과 |
| `aftermath[case]` | 미해결 피해·복구 행동·당사자 응답 | 사과 수치 하나로 갈등을 지우지 않음 |

현재 boolean 엔진에는 여러 값의 배열·객체를 그대로 조건식으로 넣을 수 없다. 구현 대안은 ① 선택 이력으로 파생, ② 꼭 필요한 배타적 결과만 FLAG로 저장, ③ 필요한 경우 별도 사건 상태 모델 추가다. 이번 문서는 ③을 이미 지원한다고 가정하지 않는다.
증거·인지 출처 구조도 현행 state에 없는 제안이다. 기존 `knowledge` boolean과 수첩 조건을 사용할 때는 사실별 직접/전언 조건을 별도로 등록해야 한다.

| 관계 결과 | FLAG_{HER,GIN,LUN,PAN,DRA}_*, bonds.stage/romance/poly | 사건 축으로 연애 상태를 자동 설정하지 않음 |

`Q-01~08`, `L-*`, `K-*`, `S-*`, `E-*`, `R-*`, `X-*`의 번호를 새 초안에 임의 배정하지 않는다. 상세 원고의 `A3`, `B5`는 문서 장면 번호일 뿐이다.

한 플레이의 주경로 결과는 위 다섯 묶음 중 하나다. 보조 사건의 사실은 별도 기존 KN/선택 이력으로 남기며 다른 주경로의 ‘완수’ 값을 자동 지급하지 않는다.
기존 Q-03의 선택 효과와 새 C5 결정이 같은 조사를 두 번 한다면 장면 확장 시 하나로 합친다. 같은 행동을 새 선택·새 보상으로 중복 등록하지 않는다.
Ch2 공통으로 모두가 얻는 사실은 직접 본 폭발·문·사고·환영이다. A의 필사, B의 시간표, C의 내부 지도, D의 장부, E의 시료 기록은 해당 획득 경로만 안다.

## 5. 조건·대체 경로·발견 순서

- 주경로 진입: `이전 관련 행동 OR 당일 공개 훅 조사`. 두 번째 항목은 항상 제공한다. 관련 사건을 전부 회피한 플레이는 neutral 일과 후 공통 사건에 도달한다.
- 정보 노출: `직접 관찰 OR 허가된 전언을 실제 들음`. 사건 경로 플래그만으로 세부 관찰을 공개하지 않는다. 예: C02-C marked에는 문양·온기 항목을 열지 않는다.
- 관계 장면: 사건 협업 이력+현재 신뢰/경계+미해결 피해+이번 장면의 의사 확인. 임계값은 정상 플레이 분포를 조사한 뒤 확정한다. 숫자만으로 키스·연애가 일어나지 않는다.
- 질투: 실제 목격자 목록/전언 source+시점+관계 기대. 기존 일정표의 장소 합집합은 ‘같은 순간 목격’ 증명이 아니므로 대사에서 직접 목격을 명시하고 기록한다.
- 공개 범위: 임무/연구/편지/신체 각각 별도다. 위험을 교수에게 알리는 데 당사자 신체 변화 공개가 필수라는 조건을 만들지 않는다.
- Ch12 대체 정보: KN_TARGET·KN_NARCISSA_DANGER가 없는 플레이에는 필요한 보호 브리핑을 제공할 수 있으나 직접 참석하고 근거를 들어야 한다. 모르는 채 R6로 남는 길도 있다.
- Ch13 대체 역할: 높은 능력·높은 호감이 없어도 공개 대피·호송·증거 전달을 맡는다. 개인 비밀을 모르더라도 학교 안전 결말을 낼 수 있다.
- 감정 효과: 반응·조건 판정 뒤 장면 끝에서 적용한다. 관계 gate는 선택 전 snapshot으로 고정하며 FLAG_PAN_NIGHT_OPEN의 최신 수정 방식을 보존한다.

## 6. 저장·엔딩·연출 구현 요구

- 저장 schemaVersion 2와 기존 거부·보존 정책은 이번 설계에서 바꾸지 않는다. 새 필드 도입 시 구세이브는 미기록 사실을 거짓 확정하지 않고 unknown으로 보정한다. 강제 마이그레이션으로 친밀 이력을 만들지 않는다.
- 세계 OUT 4축·기존 엔딩 ID는 유지한다. 새 학교·친구 성과는 코다 모듈이며 기존 ID에 의미가 다른 결과를 재할당하지 않는다.
- 현재 R1~R6의 수치 보정/임계값은 설계안이다. 실제 구현 전 정상 도달성·비로맨스 경로를 다시 측정한다. 수치 보정 직후 판정과 장면 감정 보상의 적용 시점을 혼동하지 않는다.
- 기존 가능: bg/show/form/pose/gaze/light/cue/trans, 조건부 문장·fx·장면 합류. CG는 기존 자산 사용 또는 글 연출 대체, 새 등록·생성은 이번 범위 밖이다.
- 신규 선택 기능: 다인 동시 배치·카메라 원근 이동·서명 UI·시료 확대 관찰. 없어도 선택·대사·배경으로 전체 사건을 구현 가능해야 한다. 폰트·3D·외부 자산 요구 없음.

- 새 특별 관계 장면은 구현 시 romance.ts 메타데이터와 시나리오의 triggerCondition 문자열을 일치시키고 비충족 대체 장면을 함께 만든다. 새 CG가 승인되는 경우에만 cg.ts 등록·고유 ID·중립 파일명·경험 기록 분리 규칙을 적용한다.

## 7. 구현 인수 기준
